# PRIVACYOS — Checklist de entregables del Hito 1

> Estado de trabajo: la presentación oral sigue pendiente según lo informado por el equipo. Este checklist no afirma que los entregables estén terminados; debe actualizarse con evidencia real.

## 1. Informe / propuesta en PDF
- [ ] Portada e identificación del proyecto y equipo.
- [ ] Índice.
- [ ] Introducción.
- [ ] Problema formulado sin partir por la tecnología.
- [ ] Evidencia verificable para dimensionar el problema (mínimo dos datos y sus fuentes).
- [ ] Usuario objetivo, contexto y alternativas actuales.
- [ ] Propuesta de valor concreta.
- [ ] Arquitectura de información.
- [ ] Arquitectura cliente-servidor y capas, aplicada a un caso de uso.
- [ ] Comparación de al menos dos alternativas tecnológicas con criterios explícitos.
- [ ] Decisión SPA/MPA justificada.
- [ ] Enfoque web y móvil explicado.
- [ ] Conclusión.
- [ ] Bibliografía con citas dentro del texto y enlaces verificados.
- [ ] Anexos, si corresponden.
- [ ] Revisión editorial y ortográfica.
- [ ] Exportación a PDF (máximo 25 páginas sin anexos, según pauta).

## 2. Prototipo
- [ ] Enlace público o instrucciones claras de acceso.
- [ ] Al menos tres pantallas encadenadas mediante navegación real.
- [ ] Datos de demostración verosímiles.
- [ ] Recorrido principal ensayado.
- [ ] Diferenciación visible entre demo y funcionalidades reales aún no implementadas.

## 3. Diagramas
- [ ] Mapa del producto con secciones, jerarquía y rutas.
- [ ] Diagrama propio de arquitectura: cliente, servidor, capas, responsabilidades y flujo de un caso de uso.
- [ ] Archivos exportados en formato legible dentro de `docs/`.

## 4. Presentación
- [ ] Archivo de diapositivas exportado a PDF.
- [ ] Problema, usuario y propuesta de valor claros al inicio.
- [ ] Prototipo navegable mostrado durante la exposición.
- [ ] Mapa del producto y arquitectura explicados.
- [ ] Exposición ensayada con cronómetro para un máximo de cinco minutos.
- [ ] Participación de los tres integrantes.
- [ ] Preparación de preguntas para cualquier integrante.

## 5. Repositorio GitHub
- [ ] README en español, con propósito, estado real, equipo y enlaces.
- [ ] Informe PDF en `docs/`.
- [ ] Presentación PDF en `docs/` cuando esté lista.
- [ ] Mapa del producto y diagrama de arquitectura en `docs/`.
- [ ] Carta Gantt y contrato de equipo.
- [ ] Enlaces comprobados.
- [ ] Sin secretos, claves privadas ni credenciales.
- [ ] Repositorio accesible para el docente.
- [ ] Revisiones automáticas y pruebas documentadas con resultados reales.

## 6. Criterio de cierre

No marcar una casilla como terminada hasta que el archivo exista, el enlace funcione o la validación se haya ejecutado y registrado. Las fechas de presentación deben confirmarse con el docente debido a la suspensión informada por el equipo.
